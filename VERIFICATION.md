# LT5Lyrics 1.11.6 — fixed World placement and simultaneous-player verification

* **A reproduced fixed-only placement bug:** With player feet Y 64, the earlier curved-text ground solver returned a center of Y 70.625 for a case whose corrected center is Y 65.6288. The old iteration's conservative fallback was being used as the spawn height. The new solver brackets the safe height instead, and bounds each glyph's tangent rather than exaggerating the whole line width. This is a reproducible code defect, not proof that it was the only cause of any particular screenshot.
* **Tall obstacles:** New fixed groups check collision shapes no more than one block above the player's feet. If the nominal column is a tall wall, tree or building, nearby loaded columns up to three blocks away are searched, keeping the text on its configured side and ahead. If no site is clear, the nominal X/Z and feet-level floor are retained; blocks may hide the text. The tests include full blocks, slabs, fractional/negative feet Y, pitch, both sides, distances, inaccessible/unloaded columns, and locked pins.
* **Geometry and isolation:** The checks include 3,000 randomized billboard/camera/curve ground cases, actual curved glyph and shadow tangent bounds across settings/scales, spawn position stability and locked X/Z. Existing Normal Follow, Sky placement, fixed anchor immobility, noninteractive holograms, picture, community, timing and provider checks pass. Follow and Sky position functions were not changed by this patch. Extremely large text can physically extend far above its ground-level bottom; flying or standing above a drop can leave a group floating rather than finding terrain lower down.
* **Minecraft client placement fixture:** Ran Fabric 1.21.11/Java 21 under software GL with an isolated temporary test fixture, synthetic preview lyrics, a real flat stone floor and an eight-block-high stone wall. With feet Y 71 and an obstructed intended column, the previous unbounded collision scan would have chosen a floor of Y 79.00001; the corrected spawn chose the adjacent loaded site at Z 7.0 with center Y 72.728312 (the center is above the floor because the multi-line text has height). In an unobstructed 80° downward-view case, the fixed group spawned at X -3, Y 72.728535, Z 6.5 and remained at exactly that anchor while the player moved, turned and changed pitch; the wall-case anchor also remained unchanged after moving. Follow was then separately exercised: after the player moved three blocks, the active Follow anchor moved three blocks as expected. The fixture set Visible Through Walls on to inspect the obstructed text and was not packaged. It does not reproduce every player world, camera angle, GPU or shader.
* **Unmodified release JAR:** Launched the actual remapped `lt5lyrics-1.11.6.jar` in a production-mode Fabric 0.19.3 / Fabric API 0.141.6 / Minecraft 1.21.11 client on Java 21 (software GL). No development mod classes or test fixture were on that production classpath. Fabric loaded both nested libraries, the world opened, and the community chip/card, Discord confirmation and No-return restored the typed chat draft. Offline test identity, missing Linux narrator library and Xvfb cursor warnings were nonfatal. This is a Linux software-rendering smoke test, not real Windows media playback or GPU/shader coverage.
* **Simultaneous playing sessions:** Deterministic tests inject separate fake Chrome/video and Spotify sessions and a fake provider. They verify choosing a lyric-capable playing alternative, using that player's title/clock, stable selection when current lyrics are available, explicit player and local/manual-lyric preference, returning to Automatic, paused exclusion, changed/disappeared track guards, provisional-to-word-timing upgrades, cached misses, provider reset and rejection of late worker results. At most one alternate lookup runs at a time and uses the existing enabled providers and cache/rate-limit behavior.

**Limits:** The simulated session tests do not prove live Windows SMTC or real Spotify/YouTube behavior. Windows/browser combinations may not expose multiple tabs as separate sessions, and incomplete metadata, network failures, provider availability or incorrect matches can still prevent correct lyrics. Searching another playing session sends its metadata to enabled providers. Client visual and packaged-JAR results, if performed, are listed separately below.

# Historical: LT5Lyrics 1.10.1 — verification report

That patch changed the **spawn placement of new Normal 3D groups while Follow was off**. Sky Lyrics and the Follow-mode target calculation are unchanged. ## Ground-placement behavior

* Previously, the full up/down look vector was multiplied by the configured distance. At steep downward pitch this could put the nominal fixed group below the player's feet. New fixed groups use the player's interpolated feet Y and horizontal view direction, with the existing distance and signed side/offset preserved horizontally. Looking up/down cannot drive the new group below the feet or change its horizontal direction.
* The wrapped main text and translation are measured before placement, so the group is raised enough for its initial multiline bounds, backdrop, shadow and animation margin to sit above the feet-level floor. If the spawn column contains a loaded collision shape, the mod searches upward to its surface; slabs use their actual partial height. It does not search below the player or load missing chunks. Collision checking is bounded and best effort.
* The chosen anchor is saved once. Looking around or moving afterward does not re-anchor the active fixed group. If Follow is turned off while a previously followed group is still active, that existing group remains where it was; the next new group uses the ground rule. A saved locked position retains X/Z: a later group may be raised if needed above the player's current feet, without moving the prior group.

### 1.10.0 changes and investigation

* Equivalent copied lyric lists no longer recreate the same Normal group. The existing Sky equal-list behavior is unchanged.
